# AI Coding Harness

팀 내부에서 Codex·Claude 작업을 한곳에 모아 보는 로컬 작업실입니다. 통합 채팅에 이야기하면 작업을 자동으로 분류하고, 선택한 클라이언트로 실행하거나 아이디어만 기록할 수 있습니다.

## 실행

Python 3.12+와 uv를 사용합니다.

```powershell
cd C:\DEV\workspace\harness
uv sync --frozen
uv run uvicorn app.main:app --host 127.0.0.1 --port 8765
```

[로컬 작업실](http://127.0.0.1:8765)을 엽니다. 단일 서버 프로세스로 실행하며 `--workers`와 실행 중 `--reload`는 사용하지 않습니다. 종료는 터미널에서 Ctrl+C입니다.

## 사용 흐름

1. 프로젝트를 만들거나 선택합니다.
2. **클라이언트**에서 설치·연결을 확인합니다. Windows는 네이티브 `.exe`를 사용합니다. Codex는 `codex login`, Claude는 해당 CLI에서 로그인한 사용자 설정을 사용합니다. 앱이 인증 정보를 따로 저장하지 않습니다.
3. 통합 채팅에서 **기록만** 또는 **클라이언트 실행**을 선택합니다. 기본은 기록만이며, 초기 클라이언트는 명확하게 표시된 Mock입니다. 실제 실행은 Codex 또는 Claude를 선택하세요. 설치 실패를 Mock 성공으로 바꾸지 않습니다.
4. 비워둔 작업 이름은 자동 분류합니다. `[로그인] 검토해줘`처럼 이름을 명시할 수도 있습니다. 애매한 실행 요청은 작업을 고른 뒤 다시 보내야 하며, 애매한 메모는 미분류로 보관합니다.
5. 작업 목록에서 해당 작업의 대화와 모든 클라이언트 결과를 함께 봅니다. 메시지 이동, 작업 이름 변경·합치기, 보류·완료 처리를 지원합니다. ‘로그인 작업은 나중에 하자’ 같은 명확한 기록 요청은 보류로 표시합니다. 보류 표시가 실행 취소를 뜻하지는 않습니다.
6. 작업 디렉터리·선택 파일은 **프로젝트**에서 설정합니다. 설정 저장 버튼은 현재 클라이언트·권한 선택도 보관합니다.

자동 분류는 주제 사전, 단어 일치, 최근 대화에 기반한 **로컬 규칙 방식**입니다. 모델 호출이나 외부 검색이 없으므로 분류용 토큰은 사용하지 않지만 의미를 완벽하게 이해하지는 않습니다. 여러 주제가 섞인 긴 문장을 자동으로 분해하는 기능은 없습니다. 분류 미리보기와 작업 이동으로 수정할 수 있습니다. 직접 고른 작업 이름은 해당 메시지에 적용한 뒤 초기화합니다.

## 공통 개발 가이드

[개발 가이드](docs/development-guide.md)는 모든 실행에 프로젝트 RULES.md와 함께 전달되며 규칙 화면에서도 확인할 수 있습니다. FIRST·OOP·SOLID·클린 코드의 실용적 적용과 기존 설계·아키텍처 변경의 보수적 판단을 안내합니다. 영향이 크거나 불확실한 변경은 사용자 판단을 요청하도록 지시합니다. 실행 기록에는 규칙별 해시를 저장합니다. 이는 에이전트 지침이며 시스템 차원의 변경 승인·차단 기능은 아직 구현 전입니다.

## 클라이언트 실행과 세션

- Codex: `exec --json`, 저장된 ID로 `exec resume`. 실제 설치 버전에서 첫 응답·세션 재개·수정 모드 파일 생성을 검증했습니다.
- Claude: `-p --output-format json`, 저장된 ID로 `--resume`. 이 개발 환경에는 미설치여서 실제 호출은 아직 검증하지 못했습니다. 어댑터 응답·세션 전달은 테스트 대역으로 검증했습니다.
- 모델과 플러그인 설정은 기본 클라이언트 설정을 읽습니다. 플러그인 검색·추천·설치·ON/OFF는 하네스 범위에서 제외합니다. 설치된 플러그인의 사용 여부는 클라이언트 동작을 따릅니다.
- 세션은 프로젝트·작업·클라이언트·절대 작업 디렉터리·권한 모드별로 구분합니다. 같은 클라이언트는 저장된 세션을 이어가고, 다른 클라이언트의 결과와 이후 메모는 추가로 전달합니다.
- 최대 최근 메시지 30개에서 관련 작업의 기록만 선택하고 전체 Context 32,000자 이내로 오래된 기록부터 줄입니다. 메시지당 입력 4,000자·결과 6,000자로 제한합니다. 이는 요약 모델이 아니며, 긴 대화의 모든 세부 사항을 기억하는 것은 아닙니다.
- 작업을 옮기거나 합치면 관련 네이티브 세션 연결을 지우고 다음 실행에서 현재 분류 기록으로 새 세션을 시작합니다. ‘새로 시작’도 선택할 수 있습니다. 실패·취소한 세션은 다음 실행에 재사용하지 않습니다.
- 기존 Codex·Claude 앱에서 따로 진행한 대화를 가져오는 기능은 없습니다. 이 하네스가 실행한 세션만 연결합니다.

## 실행 상태와 권한

실행은 백그라운드에서 진행되며, 화면은 약 1.8초 간격으로 상태를 갱신합니다. 결과·오류·클라이언트 제공 사용량·소요 시간을 저장합니다. 실시간 토큰/도구 로그 스트리밍은 없습니다. 기본 제한 시간은 600초, 클라이언트 stdout/stderr는 각각 4 MiB입니다.

한 프로젝트에서는 한 실행만 허용합니다. 다른 프로젝트의 실행과 메시지 기록은 가능합니다. 취소하면 자식 프로세스 종료를 시도하고 중단 상태를 저장합니다. 이미 바뀐 파일은 되돌리지 않습니다. 서버가 강제 종료되어 남은 실행은 ‘종료 미확인’으로 유지하며, 다른 프로세스까지 종료했는지 확인한 뒤 기록을 정리해야 다음 실행이 가능합니다.

검토 모드는 Codex `read-only`, Claude `plan`입니다. 수정 모드는 Codex `workspace-write`, Claude `acceptEdits`입니다. Codex의 비대화형 승인 요청은 거절하고, Claude의 추가 권한은 네이티브 정책에 맡깁니다. 승인 우회·전체 디스크 허용 옵션은 사용하지 않습니다. Claude의 모드는 OS 샌드박스와 같지 않습니다. 하네스의 파일 API 보호 규칙을 네이티브 CLI 전체에 강제하는 구조도 아닙니다.

이 버전은 각 팀원이 자신의 컴퓨터에서 실행하는 로컬 단일 사용자 도구입니다. 팀 공유 서버용 인증·사용자별 접근 제어·Git worktree 격리는 포함하지 않습니다. 서로 다른 프로젝트가 공유하는 외부 자원이나 하네스 밖에서 실행하는 CLI는 동시 실행 잠금 대상이 아닙니다.

## 파일과 저장

기본 프로젝트 위치는 `workspaces/`, DB는 `workspaces/.harness/harness.sqlite3`입니다. `HARNESS_WORKSPACES`, `HARNESS_DB` 환경 변수로 변경할 수 있습니다. 위치 변경 시 기존 데이터는 자동 이동하지 않습니다.

SQLite v3는 v1/v2의 설정·메시지·실행을 보존합니다. 재시작 후에도 기록과 클라이언트 세션 연결을 복원합니다. 트랜잭션·WAL·잠금 대기를 사용합니다. DB 백업은 서버 종료 후 DB와 남아 있는 `-wal`, `-shm` 파일을 함께 복사하거나 SQLite backup API를 사용합니다.

프로젝트 이름은 영문·숫자로 시작하고 영문·숫자·하이픈·밑줄로 최대 64자입니다. `RULES.md`는 프로젝트 루트부터 작업 디렉터리까지 읽습니다. 파일 API는 UTF-8 최대 64 KiB, Context 파일은 최대 10개입니다. 파일 API는 Workspace 밖·링크·`.git`·`.harness`·`.env` 및 `.env.*`를 차단합니다.

문서·계획은 `docs/`, 완료 보고서는 `outputs/`, 임시 검증 파일은 `work/`에 둡니다. 입력 문서 파싱·Spec 생성·Tool Gateway는 별도 후속 범위입니다.

## 테스트

```powershell
uv run --frozen pytest -q
node --check app/web/static/app.js
```

테스트에는 DB 마이그레이션, 프로젝트 경계, 자동 분류, 보류·합치기, 클라이언트 전환, 권한별 세션 분리, 실제 자식 프로세스 취소·시간 제한이 포함됩니다. 제한된 OS 환경에서는 프로세스 종료 테스트에 일반 실행 권한이 필요할 수 있습니다.

## 주요 API

- `GET/POST /api/projects`, `GET/PUT /api/projects/{name}/settings`
- `POST /api/projects/{name}/route`: 실행 없는 분류 미리보기
- `POST /api/projects/{name}/chat`: 기록 또는 백그라운드 실행. 모호하면 `needs_selection` 반환
- `GET /api/projects/{name}/tasks`, `PATCH /api/projects/{name}/tasks`: 상태·이름 변경·합치기
- `GET/POST /api/projects/{name}/messages`, `PATCH /api/projects/{name}/messages/{id}`
- `GET /api/projects/{name}/runs`, `GET /api/projects/{name}/runs/{id}`
- `POST /api/projects/{name}/runs/{id}/cancel`, `POST .../reconcile`
- `GET /api/clients`, `PUT /api/clients/{client}`

분류와 세션 계약의 근거는 [클라이언트 연동 기록](docs/client-runtime.md)에 정리합니다.
