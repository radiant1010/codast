## 이전 방향과 계획 (플러그인 관련 항목 보류)


- Backend는 FastAPI/Python을 유지한다. npm은 일부 외부 도구의 설치 수단이며 우리 서버의 실행 환경을 바꾸는 이유가 아니다.
- 실제 클라이언트를 실행하고 그 클라이언트의 플러그인·스킬·훅·하위 에이전트 기능을 활용한다. 모델 API 직접 호출에 로컬 클라이언트 설정이 자동 적용된다고 가정하지 않는다.
- 플러그인의 설치와 실행 방식은 각 클라이언트에 맡긴다. 우리 하네스에서 GSD 등의 내부 기능을 재구현하지 않는다.
- 우리 UI는 클라이언트별 설치 목록·활성 상태 조회와 지원되는 설정 변경을 연결한다. 처음에는 Codex 하나를 대상으로 한다.
- UI의 토글보다 실제 클라이언트의 조회·변경 기능 확인이 먼저다. 지원되지 않는 기능은 지원하는 것처럼 표시하지 않는다.
- ON/OFF는 다음 실행부터 적용한다. 진행 중인 작업의 설정이나 이미 변경된 파일을 되돌리는 기능으로 취급하지 않는다.
- SQLite로 설정과 실행 기록을 영속 저장한다. 소스와 문서 파일은 기존 Workspace에 유지한다.
- 플러그인이 모델 자체의 추론 능력이나 토큰 절약을 보장하지 않는다. 기본 실행과 비교해서 도입 효과를 판단한다.

- [ ] Superpowers 또는 GSD 하나를 선정하여 Codex 클라이언트에 설치. 여러 워크플로를 처음부터 중복 적용하지 않기.
- [ ] 동일한 시작 코드와 요구사항으로 기본 상태/플러그인 적용 상태의 새 실행을 비교.
- [ ] 작은 버그 수정과 여러 단계의 FastAPI 기능 구현을 각각 비교해 적정 사용 범위 결정.
- [ ] 성공 여부, 검증 결과, 재수정 횟수, 완료 시간, 제공되는 총 토큰·비용 기록. 데이터 미제공은 0으로 기록하지 않기.
- [ ] 지침이나 기존 코드 변경이 다음 비교에 섞이지 않도록 실행 상태 분리.
- [ ] 측정 결과로 기본 ON/OFF와 사용 조건 결정. 효과가 없으면 기본 상태 유지.
