# 통합 작업실과 클라이언트 실행 계약

## Codex 계정 조회 — 2026-09-16

`GET /api/clients/codex/status`는 설정된 Codex 실행 파일의 App Server를 stdio로 잠시 열고 `initialize`, `model/list`, `account/rateLimits/read`만 호출한다. 실행·재개 어댑터는 교체하지 않으며 에이전트 턴을 시작하지 않는다. [공식 프로토콜](https://learn.chatgpt.com/docs/app-server)을 사용한다. 조회 프로세스는 종료하고 결과/실패 모두 60초 캐시한다. 동시 요청을 합치며 CLI 경로 변경은 캐시를 무효화한다.

응답은 계정 범위이며 출처·확인 시각·수집 상태를 포함한다. 모델 목록 기본값은 실제 실행 모델이 아니다. 한도는 제공된 분 단위 기간·사용률·초기화 시각으로 표시하며 계정 식별자·결제·인증 데이터는 전달하지 않는다. 모델 목록은 최대 100개이고 추가 페이지 존재 여부를 별도 반환한다. 실행 모델·현재 컨텍스트 점유율은 아직 미수집이다. 실제 작업실(`/`)에 계정 요약과 상세 창을 연결했다. 정적 데모는 여전히 예시 데이터다.

로컬 `codex-cli 0.154.0-alpha.6.2`에서 모델 5개·한도 조회를 확인했다. 제한된 개발 실행 환경에서는 홈 디렉터리 조회에 실패했으나 일반 사용자 환경에서는 기존 로그인으로 성공했다. 별도 플러그인·계정 설정 변경은 필요하지 않았다. 관련 테스트 5개 통과(상태 조회 3개, 기존 세션 집계 2개), JS 문법 검사를 수행했다.

## 2026-09-16 세션 중심 UI 변경

코어 목적은 에이전트 세션과 채팅 세션 관리다. 사용자 스케치에 따라 왼쪽 프로젝트·채팅 목록, 상단 사용량·실행 중 세션, 중앙 콘솔, 하단 AI 선택·입력으로 구성했다. 문서·실행 설정·연결·기록은 보조 창으로 이동했다. 기존 작업 이름을 채팅 묶음으로 재사용하며 첫 메시지를 보낼 때 저장한다. 일반 메시지는 기본적으로 선택한 에이전트를 실행하고 자동 분류는 기본 해제한다. 새 채팅 또는 기존 채팅을 선택해야 전송한다.

`GET /api/session-overview`는 삭제되지 않은 프로젝트의 네이티브 세션 연결과 모든 running 기록을 반환한다. 현재 서버가 관리하는 실행과 종료 확인이 필요한 기록을 구분한다. 화면은 5초 간격으로 조회하며, 목록 클릭은 해당 프로젝트·채팅으로 전환한다. 채팅 안에서 AI를 바꾸면 기존 클라이언트별 세션 연결 계약을 따른다. 표시된 세션 ID가 실제 CLI에서 여전히 재개 가능하다는 보장은 아니다.

사용량은 선택 프로젝트의 전체 저장 실행을 현재 채팅·에이전트·네이티브 세션 ID·작업 경로·권한별로 집계한다. 상단은 에이전트별 누적 합계를 표시하고 + 버튼으로 에이전트별 최근 채팅 3개를 펼친다. 완료 여부와 무관하게 마지막 실행 시각 순으로 선택하며 같은 채팅의 네이티브 세션들은 합산한다. 입력·출력 토큰, 실행 횟수, 수신 기록 수, 마지막 실행 시각을 확인하고 해당 채팅으로 이동할 수 있다. 작업 중인 세션의 컨텍스트 윈도우 사용량은 미수집으로 표시한다. 미수신 값은 0과 구분하며 캐시 토큰·비용·컨텍스트 점유율을 합산값으로 추정하지 않는다. 값은 CLI가 반환하여 저장한 범위로 한정한다. 계정 한도 %와 Git 상태는 미연결이다. 알림은 이 페이지가 조회한 실행의 상태 변화만 보여주며 영구 저장하거나 짧은 모든 실행을 감지하지 않는다. 채팅별 초안 저장과 독립 채팅 ID는 후속 범위다.

## 입력과 분류

`POST /chat`은 `action=note|run`으로 기록과 실행을 구분합니다. 단, `/codex 요청`·`/claude 요청`은 명시적 실행 명령이며 기본 에이전트보다 우선합니다. 원문을 메시지에 보존하고 접두어를 제거한 요청을 Context로 전달합니다. 미지원 명령과 빈 요청은 실행 전에 거절합니다. `auto_route=true`이고 작업 이름이 비어 있으면 로컬 분류기가 `[작업 이름]`, 주제 사전, 기존 작업의 최근 사용자 대화, 후속 표현을 순서에 맞게 처리합니다. 애매한 실행은 선택 후보를 돌려주고 DB 실행을 만들지 않습니다. 메모는 미분류로 저장할 수 있습니다. 작업은 프로젝트 안의 이름으로 식별하며 이름 변경·합치기는 메시지를 재분류하고 네이티브 세션 연결을 초기화합니다.

이는 규칙 기반 분류 구현입니다. 의미 기반 모델 분류, 한 문장의 다중 작업 자동 분해, 별도 작업 ID·별칭은 후속 개선입니다. 플러그인 추천용 검색·모델 호출은 하지 않습니다.

## 네이티브 실행

[OpenAI 공식 비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)의 JSONL 완료 이벤트와 ID 기반 재개 방식을 따릅니다. 설치된 Codex 도움말도 확인했습니다. 코드에서는 전역 설정 인수로 승인 거절과 샌드박스 모드를 지정하여 신규·재개 실행 모두에 적용합니다. 모델·사용자 설정 로딩은 네이티브 기본값을 유지합니다.

[Claude 공식 프로그램 실행 문서](https://code.claude.com/docs/en/headless)의 `stream-json --verbose --include-partial-messages` 이벤트 및 최종 result와 세션 ID 기반 재개 형식을 사용합니다. 읽기 모드는 plan, 수정 모드는 acceptEdits이며 전체 권한 우회 옵션을 사용하지 않습니다. 사용자 설치 설정의 실제 로딩 여부는 해당 클라이언트 버전·프로젝트 신뢰 정책에 따릅니다.

명령은 argv 배열로 네이티브 실행 파일을 직접 시작하고, 프롬프트는 UTF-8 stdin으로 보냅니다. shell=True, cmd 문자열 조합, 임의 사용자 실행 인수는 제공하지 않습니다. Windows의 npm `.cmd` 래퍼는 자동 실행하지 않고 네이티브 `.exe` 경로를 받습니다. stdout/stderr는 제한된 버퍼로 수집하며 취소·시간 초과 시 프로세스 트리를 종료합니다.

## 상태와 세션

SQLite v4는 기존 데이터를 보존하고 run_events를 추가합니다. v3의 실행 메타데이터, 작업 상태, 클라이언트 경로, 세션 연결 테이블도 유지합니다. 실행 예약은 SQLite 쓰기 트랜잭션에서 동일 프로젝트의 running 기록을 검사합니다. 실행은 서버 이벤트 루프의 백그라운드 작업으로 진행하고 네이티브 프로세스 I/O는 스레드로 분리합니다. 정상 서버 종료 시 활성 실행을 취소합니다.

세션 키는 프로젝트·작업·클라이언트·해석된 절대 작업 디렉터리·권한 모드입니다. 마지막 네이티브 세션에 이미 포함된 성공 실행 이전 대화는 재전송하지 않습니다. 다른 클라이언트나 다른 권한 모드에서 나온 중간 결과는 전달합니다. 실행 실패·취소·작업 재분류 후에는 새 세션으로 이어갑니다. 강제 종료 기록은 사용자 확인 없이 자동으로 정리하지 않습니다.

## 실시간 콘솔과 이벤트 복원

좌측 제어판은 전체와 내부 섹션별로 접을 수 있습니다. 프로젝트·작업, 파일 체크, 문서 편집기 열기, 실행 설정, CLI 연결을 배치했습니다. Markdown 원문 편집은 넓은 모달에서 폴더 목록과 함께 제공합니다. 문서 열기는 첨부 선택을 바꾸지 않습니다. 오른쪽 하단 입력창은 고정하고 출력 영역만 스크롤합니다. 위쪽 로그를 읽으면 자동으로 아래로 이동하지 않고 새 출력 버튼을 표시합니다.

`GET /api/projects/{name}/runs/{run_id}/events`는 SSE 순번 id, run_event, 종료 end를 반환합니다. Last-Event-ID 또는 after 이후 저장된 이벤트를 재전송하며 브라우저는 순번으로 중복을 제거합니다. 연결 종료는 실행을 취소하지 않습니다. 예전 실행은 당시 저장된 최종 결과만 복원합니다.

Codex의 명령 실행·출력·파일 변경·도구 이벤트·응답, Claude의 텍스트 delta·도구 호출/결과, stderr 경고를 실제 수신 시 기록합니다. 내부 추론은 표시하지 않습니다. 출력 단위는 CLI 버전에 따르며 토큰 단위 도착을 보장하지 않습니다. 진행 이벤트는 실행당 4,096개 이후 제한 안내를 남기며 이벤트 텍스트는 8,192자까지 저장합니다. 최종 결과와 종료 이벤트는 별도 보존합니다.

2026-09-14 실제 `/codex` 요청에서 thread/turn 시작과 CODAST_STREAM_OK 응답이 실행 완료 전에 저장됨을 확인했습니다. 브라우저에서 결과 복원, 파일 열기/체크 분리, 제어판 접기 후 입력 유지도 확인했습니다. 자동 테스트는 종료 전 stdout 전달, 에이전트 우선순위·자료 전달, 재전송·프로젝트 경계, v3→v4 이전을 포함합니다. 사용자 승인 대기·재개는 후속 범위이며 현재는 비대화형 실행과 중지까지 지원합니다.

## 프로젝트 실행 환경 조회 — 2026-09-16

`GET /api/projects/{name}/environment`는 등록된 프로젝트 루트에서 Git 브랜치·변경 항목 수를 읽고, Compose의 `com.docker.compose.project.working_dir` 라벨이 프로젝트 절대 경로와 정확히 일치하는 컨테이너의 상태·포트를 조회한다. 일반 컨테이너, 다른 표기 경로 또는 WSL 경로는 자동 매핑되지 않는다. 일반 호스트 개발 서버 포트는 아직 미수집이며 Docker 포트와 구분한다. 설치 안 됨·Git 저장소 아님·조회 실패·Docker 엔진 연결 불가를 구분하고, 원시 오류나 컨테이너 환경변수는 화면에 전달하지 않는다. 15초 캐시, 도구당 8초 제한, 기존 출력 크기 제한을 적용한다. Git 변경 수는 untracked 디렉터리를 한 항목으로 셀 수 있으며 파일 수가 아니다.

근거: [Git porcelain 상태](https://git-scm.com/docs/git-status), [Docker 컨테이너 조회](https://docs.docker.com/reference/cli/docker/container/ls/). 프로젝트 매핑·캐시·미설치·실패 계약 테스트 2개와 JavaScript 문법 검사 통과.

## 기존 Codex 세션 연결 — 2026-09-16

채팅 목록 제목 옆 폴더 아이콘으로 프로젝트 루트와 cwd가 정확히 같은 저장 세션을 조회한다. 공식 App Server `thread/list`(20개씩 커서), `thread/read`를 사용하며 기본 interactive 필터를 명시적으로 확장해 exec/appServer 출처도 포함한다. 현재 데스크톱 세션이 실제 목록에 포함되고 미리보기 메시지가 수신됨을 확인했다. 미리보기는 최근 최대 10턴/20메시지, 메시지당 8000자이며 도구 로그·내부 추론은 제외한다. 현재 read 응답은 전체 저장 턴을 읽고 표시를 제한하며 응답 한도는 16 MiB다. 큰 세션의 페이지 단위 읽기는 후속 작업이다.

사용자가 데스크톱 동시 실행 중단을 확인하고 연결하면 새 이름의 로컬 채팅과 Codex 세션 ID를 단일 트랜잭션으로 저장한다. 원문 대화는 DB에 복제하지 않는다. 선택은 Codex/루트 cwd/읽기 전용으로 맞추며 다음 사용자 메시지에서 기존 resume 경로를 사용한다. 연결 자체로 모델 호출은 하지 않는다. 동일 채팅명·하네스 실행 중 연결은 차단한다. 데스크톱의 실제 실행 여부는 확인할 수 없으며 체크박스는 사용자 확인일 뿐 프로세스 간 잠금이 아니다. 권한/cwd 변경 또는 새 세션 선택 시 기존 세션 키 계약을 따른다.

검증: 관련 테스트 8개 통과, 실제 로컬 세션 4개 및 현재 데스크톱 세션 메시지 수신 확인. 실제 데스크톱 세션의 CLI 재개 실행은 아직 미검증. 근거: https://learn.chatgpt.com/docs/app-server
