# 첨부 자료 가드 — 1차 구현

2026-09-19. 설정 → 첨부 파일 보호에는 강도·추가 탐지 항목·테스트 데이터 표시 옵션만 둔다. 입력창의 클립 버튼이나 드래그앤드롭으로 여러 파일을 올리면 검사에 성공한 자료만 현재 채팅에 자동 첨부한다. 첨부 항목을 눌러 처리 내역·가공 결과를 확인하고 X로 첨부를 해제한다. 입력창에는 클립과 현재 첨부만 표시한다. 자료함·재선택·저장 자료 삭제 UI는 제공하지 않으며 첨부 해제는 기존 자료와 실행 기록을 삭제하지 않는다. 선택 자료는 다음 실행의 `context.files`로 전달된다. 원본 파일을 수정하거나 하네스 폴더에 복사하지 않는다. 자료 번호만 브라우저 초안에 보관한다.

## 구현 범위

Python 프로세스 안에서 `detect-secrets==1.5.0` 탐지기와 자체 한국어 패턴을 실행한다. 별도 실행파일·Docker·LLM 호출이 없다. 라이브러리의 `analyze_string`만 호출하며 키 유효성 확인 요청은 하지 않는다. 선택 근거는 [v1.5.0 BasePlugin 구현](https://github.com/Yelp/detect-secrets/blob/v1.5.0/detect_secrets/plugins/base.py)의 문자열 탐지와 네트워크 검증 경로 분리다. 하네스의 탐지 목록·정책은 `app/core/data_guard.py`가 관리한다. 라이브러리 전체 CLI의 탐지 범위와 동일하다는 의미는 아니다.

| 강도 | 탐지된 키·비밀번호·고위험 식별정보 | 이름·연락처·사용자 ID |
| --- | --- | --- |
| 강력 (기본) | 전체 치환, 개인키 자료 전체 차단 | 전체 치환 |
| 중간 | 전체 치환, 개인키 자료 전체 차단 | 부분 마스킹 |
| 낮음 | 전체 치환, 개인키 자료 전체 차단 | 원문 |
| 전체 허용 | 원문 | 원문 |

전체 허용에서도 탐지 내역을 기록한다. 입력창에 “보호 꺼짐: 키도 그대로 보냅니다”을 표시하며 실행 내역에서도 구분한다. 테스트 데이터 표시는 사용자가 지정하는 설명일 뿐이며 가드를 우회하지 않는다. 실제 값/더미 구별이나 인증 유효성 판정은 하지 않는다.

- 시크릿: AWS·Azure Storage·GitHub·GitLab·JWT·OpenAI·Slack·Stripe·BasicAuth·키워드 탐지, 인용된 고엔트로피 문자열, 비밀번호/키 할당문과 DB 연결 URI의 인증 부분. 모든 제공자·키 형식을 포괄하지 않는다.
- 개인정보: 한국 전화번호·주민등록번호 형태·이메일 패턴. 이름/ID와 여권·계좌 등의 값은 알려진 표 헤더 또는 `항목: 값` 라벨로 식별한다. 이름은 자유문장 전체에서 자동 인식하지 않는다. 추가 항목명으로 사내 열 이름을 등록할 수 있다. 사용자 정규식 실행은 지원하지 않는다.
- `홍길동 → 홍*동`, `010-1234-2324 → 010-****-2324`, `dkwm12345 → dkwm*****`. 부분 마스킹은 재식별 불가능성을 보장하지 않는다.

## 파일과 한도

UTF-8 TXT/MD/CSV, XLSX(openpyxl), DOCX(python-docx), PPTX(python-pptx)를 읽는다. 표 첫 행을 헤더로 사용한다. 문서 전체의 서식을 보존한 사본은 만들지 않는다. 원본 파일명과 시트명은 대신 자료 번호·위치 번호를 사용한다.

이미지/OCR·내장 객체·메타데이터는 보내지 않는다. XLSX 숨김 시트·수식·주석, DOCX 머리말·꼬리말·중첩 표·주석·변경 이력, PPTX 발표자 노트·그룹 도형·마스터는 대상 밖이다. 해당 제외 범위를 UI에 표시한다. 일반적인 지원 구조에서 추출된 텍스트만 처리하며 시각적 배치 전체를 재현하지 않는다.

8 MiB 업로드, 압축 해제 합계 32 MiB/3,000개 항목, 추출 텍스트 120,000자/10,000개 유효 항목, 셀·문단 16,000자, 처리 항목 100,000개, 탐지 10,000건으로 제한한다. XML DTD/엔티티와 NUL 포함 XML을 거절한다. XLSX 시트는 10,000행/1,000열/100,000셀 이하로 제한한다. 초과·암호화·미지원·파싱 실패 시 원본 전달로 대체하지 않는다. 실행에는 기존 합산 컨텍스트 32,000자 제한도 적용되므로 등록 성공과 실행 가능 크기는 다르다. 대용량 순차 처리·진행률·취소·OCR은 후속 범위다.

## 보관과 전달 기록

DB v9의 `materials`에는 가공된 텍스트와 값 없는 보고서만 저장한다. 낮음/전체 허용에서는 정책에 따라 원문 값이 남으므로 DB·백업은 계속 개인 데이터다. DB는 암호화하거나 네이티브 CLI 접근을 격리하지 않는다. SQLite 삭제는 보안 삭제가 아니며 이전 백업·WAL에 흔적이 남을 수 있다. 프로젝트별 100개, 실행별 최대 10개 선택을 지원한다.

자료는 등록 당시 규칙 버전·설정 지문에 묶인다. 다음 실행 준비 시 현재 설정과 다르면 거절한다. 원본을 저장하지 않아 다시 업로드해야 한다. 이미 준비되거나 시작한 실행은 그때의 정책 스냅샷을 사용한다. 서로 다른 프로젝트의 자료 ID는 재사용할 수 없다.

실행 접수와 함께 `metadata.guard`를 저장하고 어댑터 호출 직전에 `dispatch_attempted`를 기록한다. 프로젝트/채팅/실행과 자료 ID·강도·규칙 버전·위치·정보 유형·조치·건수를 연결한다. 탐지된 값·원본 파일명은 보고서에 넣지 않는다. “전달 시도”는 모델이 실제로 내용을 소비했다는 확인이 아니다. 선택 자료 삭제 후에도 기존 실행의 감사 내역은 남긴다.

**적용 경계:** 첨부 자료만 검사한다. 채팅 본문, 이전 대화, 룰북, 기존 `context_paths`, 에이전트의 직접 파일 읽기·도구 결과·응답·실행 로그는 이 가드를 거치지 않는다. 기존 네이티브 세션의 내용을 회수하거나 가드 변경 시 자동으로 세션을 분리하지 않는다. 강력도 탐지된 값에 대한 정책이며 모든 민감정보가 사라졌다는 보장은 아니다. OS/CLI 접근 경계와 전체 전달 경로 가드는 별도 작업이다.
