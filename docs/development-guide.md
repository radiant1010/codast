# 공통 개발 가이드

이 문서는 CODAST 개발과 실행 시 전달하는 기본 규칙이다. 사용자 요청, 상위 지침과 실행 환경의 권한 정책을 우선한다.

## 작업 범위

- 현재 Git 상태, 관련 코드와 테스트를 확인하고 사용자 변경을 보존한다.
- 의견이나 질문을 구현 승인으로 확대하지 않는다. 이미 승인된 범위의 일상적 작업은 같은 승인을 반복해서 요구하지 않는다.
- 기존 기능과 구현을 재사용하고 요구사항을 충족하는 작은 변경을 선택한다. SOLID, OOP와 FIRST는 필요한 품질을 위한 기준이며 불필요한 계층이나 절차를 늘리는 목적이 아니다.
- 구조 변경은 보수적으로 처리한다. 중요한 정책, 데이터 형식과 호출 관계를 바꾸거나 승인 범위를 벗어나는 경우 영향, 대안과 검증 계획을 준비한다.
- 사용자 판단 필요 사항은 구체적인 결과와 함께 설명한다. 사용자 결정 전 해당 변경은 보류하되 독립적으로 가능한 작업은 진행한다. 침묵을 승인으로 취급하지 않는다.

## 구현과 검증

- 정상 동작, 오류, 경계 조건과 필요한 복구 경로를 요구사항에 따라 검증한다.
- 테스트를 통과시키려고 명세나 기대 조건을 임의로 낮추지 않는다.
- 실제 실행한 검사와 결과, 변경 이유, 남은 제약과 미검증 범위를 보고한다. CLI 정상 종료를 결과 품질이나 사용자 승인으로 간주하지 않는다.
- 가정, AI의 제안과 사용자 결정을 구분한다. 중요한 기술 판단에는 관련 코드, 검증 결과나 확인한 공식 근거를 제시한다.
- 공개 배포, 과거 이력 재작성과 원격 강제 푸시는 사용자 승인 범위를 확인한 뒤 수행한다.

## 개인 데이터와 공개 배포

- 공개 문서는 README, 기본 개발 규칙과 가상 작업 지시서 예시로 제한한다. 상세 설계, 브레인스토밍, TODO, 회고와 검증 기록은 `docs/internal/`에 보관한다.
- 내부 폴더는 Git, Docker 빌드와 Git archive에서 제외한다. 제외 설정은 접근 통제나 백업을 제공하지 않으며 이미 커밋된 과거 내용을 삭제하지 않는다.
- 회사와 고객의 비공개 업무 내용, 실제 계정 ID와 인증정보, 개인 설정, 실행 DB와 원문 로그를 공개 파일에 복사하지 않는다. 검증에는 가상 자료를 사용한다.
- 회사 자료는 회사가 허용한 위치와 이용 범위에서만 관리한다. 내부 폴더가 회사 자료의 저장과 이용 권한을 부여하지는 않는다.
- 커밋과 공개 전 실제 파일 목록과 diff를 확인한다. 제외 대상의 강제 추가를 하지 않는다.
- 기존 `docs/development-guide.md` 경로와 RuleLoader 전달 동작을 유지한다. 내부 문서는 실행이나 배포의 필수 입력으로 사용하지 않는다.
