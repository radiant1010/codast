## 사용자가 합의한 방향

- 제품은 로컬 CLI 기반 개발 작업실이다. 현재 상태를 완성된 MVP라고 부르지 않는다.
- 하나의 대화에서 `/codex 요청`, `/claude 요청`으로 사용자가 에이전트를 선택한다.
- 목표 흐름: 첨부 자료 → 요구사항 정의 → 다른 에이전트의 설계 → 설계 검토 → 확정한 설계를 바탕으로 구현.
- UI는 좌측 접이식 제어판, 우측 CLI 형태의 실행 기록, 하단 입력창이다. 상단 탭과 결과 카드 위주 화면으로 되돌리지 않는다.
- 반복 동작은 아이콘과 툴팁을 사용하고 입력칸 오른쪽 같은 줄에 배치한다. 시작 안내와 설정 이름은 읽을 수 있는 문구를 유지한다.
- 테스트 FIRST, 실용적 OOP·SOLID·클린 코드, 낮은 결합도와 필요한 확장성을 기본으로 한다. TDD는 일괄 강제가 아니다.
- 중복 제거·상속은 예시이지 의무가 아니다. 불필요한 기능·계층·패턴·설정·검증 절차를 추가하지 않는다.
- 기존 설계·아키텍처 구조 변경은 사이드 이펙트·호환성·호출부 영향에 근거해 보수적으로 판단한다. 기존 구조를 무조건 유지하라는 뜻은 아니다.
- 부하·멱등성·동시성·일관성·재시도·복구·원인 추적은 관련 있는 범위에서 검토한다. 가정·실측·AI 추천을 구분한다.
- 설계·기술 판단에는 레퍼런스 링크가 필요하다. 공식 문서·표준·원 논문, 실제 코드 위치와 측정 기록을 연결하고 확인하지 않은 자료를 인용하지 않는다.

## 현재 확인한 환경과 Git

- 작업 경로: `C:\DEV\workspace\harness`
- Windows / PowerShell, Python 3.12 이상, FastAPI + SQLite + 일반 HTML/CSS/JavaScript.
- 브랜치: `main`
- 원격: [radiant1010/codast](https://github.com/radiant1010/codast)
- 문서 작성 직전 HEAD: `412f1c1` — `docs: 개발가이드 초안 작성(기본 값)`
- 작성 직전 `git status --short`는 비어 있었다. 이전 대화의 “아직 커밋하지 않음”은 현재 상태와 다르다. 원격과의 동기화 여부는 이번에 확인하지 않았다.
- 로컬 서버 [127.0.0.1:8765](http://127.0.0.1:8765/)의 `/health` 응답은 정상이다. `MockAgentAdapter` 표시는 기본 테스트 어댑터이며 실제 Codex 실행을 지원하지 않는다는 뜻은 아니다.
- 서버를 중복 실행하지 않는다. 재시작 전 진행 중인 작업을 확인한다. 이전 도구의 프로세스 ID나 세션 ID를 새 세션에서 그대로 신뢰하지 않는다.
- 기본 DB: `workspaces/.harness/harness.sqlite3`, SQLite 스키마 v4.
- `outputs/`, `work/`, 워크스페이스와 DB는 로컬 전용이다. Git에는 소스·테스트·유지할 문서를 남긴다. 과거 outputs 추적 제거는 이미 처리했으며 Git 기록을 다시 수정하지 않는다.

## 구현된 기능

### 프로젝트와 파일

- 앱 내부 프로젝트 생성, 기존 외부 폴더의 워크스페이스 등록.
- 외부 폴더는 복사·초기화하지 않는다. 내부 등록 디렉터리 `.harness/workspace.json`에 실제 경로를 저장한다.
- `ProjectManager.entry()`는 내부 등록 위치, `select()`는 실제 작업 루트를 반환한다. 책임 분리 시 이 차이를 유지한다.
- 삭제는 내부 `.harness/deleted.json` 표시를 통한 휴지통 처리다. 파일·기록을 보존하고 복원할 수 있다. 외부 폴더는 이동·삭제하지 않는다.
- 실행 중/종료 미확인 작업이 있으면 삭제를 차단한다. 삭제한 이름과 동일한 외부 경로를 다른 프로젝트로 재등록하지 못하게 한다.
- Windows 폴더 선택은 서버 측 PowerShell / FolderBrowserDialog 호출이다. 로컬 Windows 데스크톱에서만 사용한다. 구성 요소 로딩과 선택/취소 응답 계약은 검증했지만 실제 사용자의 네이티브 창 선택은 수동 검증 대상이다.
- 파일 API는 등록 루트 밖·링크·보호 경로를 차단한다. UTF-8 파일 64 KiB, 선택 파일 최대 10개, 전체 Context 32,000자 제한이 있다.

### 대화와 CLI

- 명시적 `/codex`, `/claude` 명령은 기본 에이전트·기록 모드보다 우선한다. 원문은 기록하고 접두어를 제거한 요청을 에이전트에 전달한다.
- 작업별 보기·이동·합치기·보류·완료 및 로컬 규칙 기반 분류. 의미 기반 모델 분류나 문장 자동 분해는 없다.
- 백그라운드 실행, 프로젝트별 실행 제한, 취소·시간 제한, 네이티브 세션 재개.
- 세션 키는 프로젝트·작업·클라이언트·실제 절대 작업 디렉터리·권한 모드다.
- CLI 이벤트를 SQLite `run_events`에 저장하고 SSE로 전달한다. 재접속 시 순번으로 이어받는다. 과거 로그도 펼쳐볼 수 있다.
- Codex 실제 실행·응답·세션 재개·수정 모드 테스트 및 완료 전 이벤트 수신을 확인했다.
- Claude CLI는 이 환경에서 실제 실행을 검증하지 않았다. 사용자는 회사 계정을 연결할 예정이다. 개인 결제·로그인·설치를 임의로 진행하지 않는다. Claude Desktop 실행 파일을 CLI로 등록하지 않는다.

### 화면

- 초기 4단계 준비 안내: 프로젝트 → 에이전트 → 작업 범위 → 첫 요청. 진행 표시는 브라우저에 프로젝트별로 보관한다.
- 참고 파일 제목 오른쪽의 문서 아이콘에서 넓은 편집 모달을 연다. 별도 문서 아이콘 행을 다시 만들지 않는다.
- 모달에 폴더별 문서 목록·검색·Markdown 필터·원문 편집·새 문서·저장·Ctrl+S가 있다. Markdown 렌더링 미리보기는 아직 없다.
- 파일 열기와 첨부 체크는 별개다. 모달 편집 중 대화와 작성 중 요청을 유지한다.
- 미저장 변경 확인과 저장 전 변경 감지가 있다. 외부 편집기와의 원자적 동시 쓰기 잠금은 아니다. Windows 줄바꿈 정규화를 고려한다.
- CSS로 드롭다운을 조정했다. `appearance: base-select` 지원 브라우저에서는 펼친 목록까지 스타일을 적용하고, 미지원 환경은 기본 선택 동작을 유지한다. CDN은 추가하지 않았다.


## 아직 구현하지 않은 코어

- 단계별 산출물의 파일·버전·생성 에이전트·입력 자료·검토 상태 연결.
- 확정본과 초안을 구분하여 다음 에이전트에 명시적으로 전달하는 기능.
- 중요한 구조 변경에 대한 사용자 판단 대기·승인·거절·재개와 서버 재시작 복원.
- 실행 요청 식별에 기반한 멱등성 보장. 프로젝트당 실행 제한은 같은 요청의 재실행 방지와 다르다.
- 실제 부하 측정과 용량 검증, DB 백업·복원 실검증.
- 명시적으로 요청한 스킬·플러그인의 사용 가능 여부와 실제 사용 증거 표시.
- 회사 Claude 계정을 통한 전체 흐름 검증.

플러그인 검색·추천·설치 플랫폼, 팀 공유 서버 인증, worktree 격리, 분산 실행은 현재 우선 범위가 아니다. 공통 룰북이 주입된다고 위 기능이나 구조 변경 차단이 구현된 것으로 간주하지 않는다.
