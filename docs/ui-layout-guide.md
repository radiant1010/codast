# UI 레이아웃 가이드

하네스의 새 화면과 기존 화면 수정에 적용한다. 사용자 시안을 우선하며 공통 규칙은 [개발 가이드](development-guide.md)의 버튼·아이콘 규칙과 함께 따른다.

## 간격과 정렬

| 대상 | 규칙 |
| --- | --- |
| 모달 내부 | 기본 24px, 좁은 화면 20px |
| 모달 제목·본문 | 24px 간격 |
| 입력 항목 사이 | 16px |
| 라벨·입력칸 | 8px |
| 입력칸·관련 버튼 | 같은 줄, 12px 간격 |
| 입력·아이콘 버튼 높이 | 한 줄 입력 기준 40px |
| 섹션 사이 | 24px |

- 라벨은 입력칸 위에 두고 `for`로 연결한다. 안내·오류는 해당 항목 아래에 표시한다.
- 하나의 입력에 직접 작용하는 추가·등록·검색 버튼은 입력 오른쪽에 둔다. 버튼이 입력 아래로 떨어지지 않도록 입력은 남은 폭을 차지하고 버튼 폭은 고정한다.
- 여러 항목 전체에 작용하는 완료·다음 버튼은 섹션 하단 오른쪽에 둔다. 개별 입력 버튼과 구분한다.
- 모달 제목은 왼쪽, 닫기 X는 오른쪽 같은 줄에 둔다. 닫기를 본문이나 입력 행에 배치하지 않는다.
- 섹션 제목은 왼쪽에 두고 새로고침·폴더 같은 헤더 동작은 오른쪽에 한 그룹으로 묶는다. 그룹 내부 간격은 8px이며 아이콘을 제목과 균등 분산하지 않는다.
- 좁은 화면에서는 입력 폭이 줄어들고 버튼은 유지된다. 긴 경로·문구 때문에 가로 스크롤이 생기지 않도록 `min-width:0`과 줄바꿈을 사용한다.

## 버튼과 상태

- 공통 `actions.js`의 SVG를 재사용한다. 새 항목 추가는 plus, 폴더·경로는 folder, 연결 확인은 plug, 완료는 check, 닫기는 close.
- 기존 대화·세션 불러오기는 문서와 안쪽 화살표 형태의 importDocument를 사용한다. 실제 폴더·경로 선택과 구분한다.
- 아이콘에 실제 동작을 설명하는 `aria-label`과 `title`을 제공한다. 키보드 포커스를 유지하고 폼은 Enter로 제출할 수 있게 한다.
- 한글 버튼은 의미 전달에 필요한 경우 검토 후 사용한다. 개인 일정·장소·대화 메모를 제품 문구에 넣지 않는다.
- 상태는 색상을 입힌 `●`와 설명을 함께 표시한다. 미연결과 오류, 정상 인증과 실행 성공을 구분한다.

## 구현과 검증

- 공통 간격 토큰과 `.modal-form`, `.form-field`, `.field-action-row`를 사용한다. 기존 `.client-path-row`에도 같은 입력 행 규칙을 적용한다.
- 모달의 기본 여백·제목 정렬·입력 높이는 `sessions.css`에서 관리한다. 화면마다 숫자나 별도 인라인 스타일을 복제하지 않는다.
- 수정한 화면에서 입력과 버튼의 같은 줄 정렬, 좁은 폭, 키보드 제출·닫기를 확인한다. 레이아웃 변경만으로 기존 동작이나 데이터 저장 방식을 바꾸지 않는다.
- 새 채팅과 연결 입력 행부터 적용한다. 미검토된 기존 화면 전체가 준수한다고 간주하지 않는다.
